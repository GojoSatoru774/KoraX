Abstract

KoraX is a proposed decentralized, open-source cryptocurrency network. Its goal is to enable users to send and receive digital assets without relying on a central authority to validate every transaction.

The project is inspired by the principles of open cryptocurrency networks: transparency, independent verification, security, and public participation.

This document describes the vision, objectives, and proposed parameters of KoraX. It does not claim that the network is already operational.

1. Introduction

Traditional financial systems generally rely on intermediaries to transfer value. Cryptocurrency networks offer an alternative approach: participants can verify transactions according to shared rules enforced by software.

KoraX aims to develop a publicly accessible network whose operation can be independently reviewed, tested, and improved by a community of contributors.

2. Vision and Objectives

KoraX has the following objectives:

- Enable transfers of KORX between users.
- Develop open-source software.
- Publish transparent operating rules.
- Allow independent verification of transactions.
- Build a network designed to withstand failures and centralized control.
- Encourage participation from developers and users.

These objectives must be demonstrated through development and testing.

3. The KORX Token

KORX is the proposed token of the KoraX network.

The proposed economic parameters are:

- Proposed maximum supply: 20,000,000 KORX.
- Proposed creator allocation: 5,000,000 KORX.
- Proposed creator share: 25% of the maximum supply.
- Remaining supply: 15,000,000 KORX, with its allocation still to be determined.

These figures are design proposals. No tokens should be considered created or distributed until the corresponding mechanisms have been implemented and verified.

The maximum supply must be enforced by the software rules, not merely declared in this document.

4. Proposed Network Architecture

The KoraX network will require several essential components.

4.1 Transactions

Users will be able to create cryptographically signed transactions to transfer tokens.

4.2 Validation

Network nodes will validate transactions according to protocol rules and reject transactions that do not comply.

4.3 Distributed Ledger

The network must maintain a consistent record of transactions. The storage and synchronization mechanisms will be defined in the technical specification.

4.4 Consensus

A consensus mechanism must allow participants to agree on the valid state of the ledger. The exact mechanism remains to be defined and tested before launch.

4.5 Security

Security will depend on cryptography, transaction validation, software testing, and public review of the source code.

5. Decentralization and Open Source

KoraX source code is intended to be publicly accessible so that anyone can review it, propose improvements, and contribute to development.

Publishing source code alone does not guarantee effective decentralization. Decentralization will also depend on the diversity of operators, the distribution of validation power, and network governance.

6. Issuance and Distribution

The final KORX issuance rules have not yet been established.

Before launch, the project must specify:

- The amount created at launch.
- Whether participant rewards will exist.
- Distribution rules.
- How the creator allocation will be handled.
- Protections against exceeding the maximum supply.
- Conditions for possible protocol changes.

No distribution should be described as completed before it can be verified on the network.

7. Preliminary Roadmap

October 11, 2026 — White paper publication

Initial publication of the project vision and proposed parameters.

October–November 2026 — Development

Define the technical specification, consensus mechanism, and monetary rules. Develop the essential components.

December 1, 2026 — Testnet target

Target date for a test network, provided a sufficiently functional version is available.

December 2026 — Testing and fixes

Test transactions, security, consensus, and supply limits. Address identified issues.

January 1, 2027 — Mainnet target

Proposed public launch date for the main network, provided the required components are complete, tested, and considered sufficiently secure.

These dates are preliminary and may be postponed. Network security and correct operation take priority over the schedule.

8. Governance

During development, improvement proposals may be published and openly reviewed.

Contribution procedures, change approval, and decision-making processes must be defined before launch. Changes affecting monetary supply or consensus rules must be documented.

9. Risks

KoraX is an experimental project and involves several risks:

- Software errors that could result in losses.
- Technical or cryptographic vulnerabilities.
- Insufficient adoption.
- Limited or nonexistent liquidity.
- Significant token price volatility.
- Regulatory uncertainty across jurisdictions.
- Development delays.

KORX has no guaranteed price, return, or liquidity. Users should understand the risks before using the network.

10. Current Project Status

As of this version, this white paper describes a project in development.

Publication of this document does not mean that the mainnet exists, that tokens are transferable, that a consensus mechanism is operational, or that a market value has been established.

Technical announcements should be supported by verifiable evidence when the corresponding features become available.

11. Conclusion

KoraX aims to become an open, transparent, and accessible cryptocurrency network. Achieving this goal will require a functional protocol, rigorous testing, and participation from independent contributors.

This white paper is an initial working document. It may be revised as technical decisions are finalized and software development progresses.
